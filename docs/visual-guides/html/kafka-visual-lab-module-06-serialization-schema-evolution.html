Mental model

Kafka lưu bytes; ứng dụng chịu trách nhiệm về ý nghĩa

Producer boundary

Serializer<T> biến key/value thành byte[].

Kafka boundary

Broker lưu record bytes cùng metadata; không kiểm tra business field.

Consumer boundary

Deserializer<T> phải biết target type và contract tương thích.

Hai loại lỗi khác nhau: invalid JSON/type mismatch có thể fail trong deserializer; JSON hợp lệ nhưng amount âm có thể chỉ fail khi business listener xử lý.

Malformed JSON

Delegate deserializer fail; record-level listener không được gọi.

Constructor invariant

Lab B · Spring Boot

Cấu hình JSON contract cố định, ít coupling

Lab dùng Spring Kafka hiện hành với JacksonJsonSerializer/JacksonJsonDeserializer. Ta chủ động tắt Java type header và đặt target type phía consumer.

Tạo topic contract lab

orders.contract.v1 và topic mặc định orders.contract.v1-dlt, cùng số partition khi recoverer giữ nguyên partition.

Cấu hình serializer/deserializer

spring:
  kafka:
    bootstrap-servers: localhost:9092,localhost:9094,localhost:9096
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JacksonJsonSerializer
      properties:
        "[spring.json.add.type.headers]": false
    consumer:
      group-id: order-contract-lab
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.ErrorHandlingDeserializer
      properties:
        "[spring.deserializer.value.delegate.class]": org.springframework.kafka.support.serializer.JacksonJsonDeserializer
        "[spring.json.value.default.type]": com.dream.learning.kafka.contract.OrderEvent
        "[spring.json.use.type.headers]": false
        "[spring.json.trusted.packages]": com.dream.learning.kafka.contract

Thêm ErrorHandlingDeserializer trước DLT

Quan sát malformed JSON không đi vào listener. Error handler nhận failed record cùng exception header/raw bytes.

DLT serializer phải xử lý raw bytes

Với deserialize failure, recoverer khôi phục payload gốc dạng byte[]. Cấu hình đường publish DLT bằng ByteArraySerializer hoặc DelegatingByTypeSerializer cho cả object bình thường và raw bytes.

Active recall

Trả lời trước khi mở

1. Kafka broker có biết payload là JSON hợp lệ không?
Không. Broker lưu bytes và metadata. Serializer/deserializer hoặc schema tooling phía client chịu trách nhiệm về format/contract.
2. Vì sao malformed JSON có thể không vào được @KafkaListener?
Deserialization xảy ra khi consumer tạo object từ bytes, trước khi record-level listener business được gọi.
3. Thêm optional field luôn backward-compatible không?
Không thể nói “luôn”. Nó thường an toàn với old consumer bỏ qua unknown field, nhưng strict consumer hoặc validation khác vẫn có thể fail.
4. Rename orderId thành id có gì nguy hiểm?
Old consumer vẫn tìm required field orderId. Cần giai đoạn migration như dual field/dual read thay vì đổi ngay.
5. ErrorHandlingDeserializer giúp gì?
Nó bọc delegate deserializer; khi delegate fail, framework giữ exception/raw bytes trong header để error handler xử lý thay vì để poll loop không có failed record usable.
6. Vì sao DLT producer cần xử lý byte[]?
Với deserialization failure, recoverer có thể publish lại raw value bytes gốc. JSON serializer dành cho object không phải lựa chọn đúng duy nhất cho payload này.
7. Retry malformed JSON 100 lần có ích không?
Thường không, vì bytes không đổi. Cần recovery/quarantine và sửa contract hoặc dữ liệu; retry dành cho lỗi có khả năng transient.
